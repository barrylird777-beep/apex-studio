# APEX Canonical Lineage Ledger

**Purpose:** preserve the founding roles and historical name mutations of the six current apps without reviving obsolete products or erasing their useful capabilities.

**Evidence rule:** this is a repository-backed reconstruction. A Git commit date proves that a name or implementation existed in the repository by that date; it does not prove that the idea was first conceived then. Where a direct rename or absorption is not explicitly recorded, the relationship is marked as an inference rather than a fact.

## Current canon — exactly six apps

1. **PlanetApeX — the Brain:** Bible study, research, knowledge, AI-assisted study, analytics, world/universe experiences, and the GardenApex living universe.
2. **XShield — the Shield:** security, privacy, ad/tracker blocking, DNS/content filtering, and protected connectivity.
3. **KernelVision — the Eyes:** the production and media studio: creative development, scripts/scenes, video/animation/VFX, editing, mixing/mastering, rendering, QC, publishing, Special Search, and production analytics. The continuous entertainment stream belongs here as a product experience, not as a seventh app.
4. **KoinKob — the Economy Lab:** worker/agent economies, asset markets, barter/value exchange, market clearing and settlement, systemic/adversarial events, and economic simulation.
5. **KashKorner — Money and Data:** cash flow, financial records and transactions, crypto/data capabilities, opportunity surfaces, connectivity coordination, and the public-facing rapid video-rendering/storefront offer.
6. **Kernelodies — the Ears:** music and sound listening, creation, discovery, libraries, artists/albums/genres, playback, audio identity, and music-specific AI/media capabilities. Jesus Freaks / KORNS PEOPLE-created music retains the locked 432 Hz rule.

The current list is corroborated by [README.md](../../README.md), [MASTER-ARCHITECTURE.md](../MASTER-ARCHITECTURE.md), and the canonical six-app navigation in [SixAppHub.tsx](../../src/pages/SixAppHub.tsx).

## Timeline of the mutations

### Stage A — three foundational systems and the first product lineup

An early repository architecture described three broad systems:

- **GardenOfApex:** research, knowledge, Bible/scripture, Korn World, studies, analytics, and AI Chat Lab.
- **Apex Studio / ApexStudios:** creative production, operations, distribution strategy, network/infrastructure, and creative interfaces.
- **KORNKNOB / KornKnob:** AI models/providers, routing/evaluation, and media-AI capabilities; some early product descriptions also used this name directly for music/audio.

The same early README recorded a six-surface lineup: **KornKnob, TeeVee, PayPex, ApexStudio, GardenOfApex, XShield**. That lineup is historical, not an additional set of apps. See the [early six-app canon commit](https://github.com/barrylird777-beep/apex-studio/commit/e9e05443c9a9b7c70879793bcb75281b4fdfcb18).

### Stage B — opportunity, rapid-video, and network names

The repository later recorded **Apexus** as replacing the earlier **ApexRapid** product concept. The Apexus specification describes a continuous 24/7 original animated entertainment network, while the earlier ApexRapid concept was a rapid customer-video fulfillment offer. A separate historical **PayPex** surface owned money-making stock/market/business and monetization intelligence; **EngineApex** was an opportunity-decision layer. See the [Apexus canon commit](https://github.com/barrylird777-beep/apex-studio/commit/4e09e42db426cf1b435f9b364a7c81a2f8e2ff7e), [Apexus network specification](../APEXUS_NETWORK_CANON.md), and [EngineApex implementation history](https://github.com/barrylird777-beep/apex-studio/commit/29534ebdd1da14406564b5c8fbafff3ad1a365da).

These names describe historical products or capability surfaces. They do not authorize creating Apexus, ApexRapid, PayPex, or EngineApex as extra canonical apps.

### Stage C — the six-name product-level canon

On 8 October 2026, the repository locked a different six-app product lineup:

**PlanetApeX, KoBlocks, KernelVision, KoinKob, KashKorner, Kernelodies.**

The commit explicitly described KoBlocks as modular building blocks, KernelVision as the finished-work viewing surface (KernelVision Theatre and Kornmax), KoinKob as economy/value/barter/worker markets, KashKorner as cash/ledger, and Kernelodies as music/audio. See the [canonical six-app commit](https://github.com/barrylird777-beep/apex-studio/commit/4681e3909a5f6a1735c77084c5625ac4a0576add) and [PR #222](https://github.com/barrylird777-beep/apex-studio/pull/222).

This was a product-level ownership change, not evidence that every older implementation module was deleted or that all legacy data had already been migrated.

### Stage D — XShield restored as the sixth canonical app

On 13 October 2026, the registry was corrected: **XShield replaced KoBlocks in the six-app list**. KoBlocks remains a reusable workflow-composition/validation capability, with its records and namespace kept outside the six canonical app identities. See the [canonical registry correction](https://github.com/barrylird777-beep/apex-studio/commit/ec60c522ae) and [PR #474](https://github.com/barrylird777-beep/apex-studio/pull/474).

The current spelling rule is also explicit: **GardenOfApex** is the historical product/system name; **GardenApex** is the living Jesus Freaks / KORNS PEOPLE universe inside PlanetApeX. It is not a seventh app.

## Historical names and where they belong

- **Apex Studio / ApexStudios:** historical production/system identity → KernelVision's production ownership.
- **GardenOfApex:** historical research/world system → PlanetApeX; **GardenApex** is the current living-universe name inside it.
- **KORNKNOB / KornKnob / KORN-KNOB:** historical music/audio product and broader AI/model/media capability layer → music-facing capabilities in Kernelodies; generic provider/model infrastructure may remain shared capability, not a seventh app.
- **TeeVee:** 24/7 programming, scheduling, episode catalog, and broadcast lineage → KernelVision.
- **ApexRapid:** rapid customer-video fulfillment lineage → public renderer/storefront offer in KashKorner. Its later **Apexus** 24/7 network identity is a separate historical mutation whose surviving entertainment-production/broadcast capabilities belong with KernelVision.
- **Apexus:** historical 24/7 original animated entertainment network → KernelVision; not a canonical app.
- **PayPex:** money-making opportunity, market/business, and monetization intelligence → relevant opportunity and financial capabilities in KashKorner.
- **EngineApex:** opportunity-decision logic and some connectivity/operational capability → preserve as an implementation/capability boundary; assign only relevant cash/opportunity/connectivity behavior to KashKorner, not the entire module by name alone.
- **ShieldApex / ApexAdBlocker:** historical security/ad-blocking surfaces → XShield.
- **KoBlocks:** reusable workflow blocks/composition/validation → shared capability, not an app.
- **KernelVision Theatre / Kornmax:** viewing experiences → KernelVision, not separate apps.
- **Music Radar:** integration/discovery client surface → Kernelodies integration; it does not supersede KernelVision as final production authority.

## Guardrails for future changes

1. Exactly six canonical app identities; no legacy name is automatically a seventh app.
2. A rename does not prove that its data or runtime has been migrated. Preserve records, files, routes, and production artifacts until reconciliation is verified.
3. Do not conflate similar names: **KoinKob ≠ KORNKNOB**; **GardenOfApex ≠ current GardenApex spelling/role**; **ApexRapid ≠ Apexus's later network identity**.
4. Shared capabilities do not erase app boundaries. Maintain independent identities, authorization, and data namespaces.
5. Treat this ledger as a mapping and research index, not proof of completed runtime migration. Verify active routes, app registries, data namespaces, and production flows separately before claiming every app is caught up.
6. Repository commit dates mark the earliest evidence found in this repository, not necessarily the user's original conception date. Earlier conversation artifacts may contain older founding decisions and should supersede an inference when directly supported.
