# PlanetApeX canon recovery

## Current canon
- PlanetApeX is the app and the BRAIN of the Apex universe.
- PlanetApeX absorbs GardenOfApex and earlier related names/concepts as historical lineage; they are not separate current apps.
- The six projects remain separate. Shared capabilities must use explicit, versioned contracts rather than merging codebases.
- Do not rename, delete, deploy, or rebuild other projects as part of this recovery.

## Historical evidence
- A GardenOfApex application contract was committed on 2026-10-07.
- Bible Study Room integration followed on 2026-10-07.
- Its code defines Scripture study notes, evidence labels (KNOWN, OBSERVED, INFERRED, UNKNOWN), sources, cross-references, version comparisons, context fields, and production handoffs.
- Earlier registry/page code represented GardenOfApex as a legacy supporting system. That is historical implementation, not current product canon.

## Verified implementation limits
- PlanetApeX has code for worlds, regions, entities, validation, and status reporting.
- The current world-builder page has no server persistence contract. Browser-local persistence is not equivalent to shared or server-side storage.
- Bible Study Room note storage defaults to an in-memory Map. It is not durable by default.
- A module's declared capability or status response does not prove that a complete user-facing workflow, AI service, analytics pipeline, or deployment is operational.
- The full original name timeline and live PlanetApeX deployment status remain unverified.

## Interconnection rule
Keep each project independently owned. Cross-project abilities should be exposed through documented, versioned interfaces with explicit permissions, timeouts, and failure handling. PlanetApeX coordinates shared context; it does not own the other projects' code.

## Change boundary
This record documents recovered canon and implementation facts. It does not authorize renaming, deleting, merging, or deploying other projects.
